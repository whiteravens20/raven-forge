# Raven Forge — visual assets

All files are self-contained SVG (no external refs, no live `<text>`, no JS). Every file has a `viewBox` and no fixed `width`/`height`, so scale freely. Verified to parse as XML; sizes below are as-shipped.

Design direction: flat/near-black grounds, a single geometric raven mark (built from straight edges, not freehand curves), violet `#7c3aed` used once per asset as a deliberate accent rather than a running color. No chrome, bevels, flames, or neon — restrained, grid-built, contemporary.

## Design notes

- **The raven mark is a hard-edged head in profile** — crown, a sharp brow kink, a flat wedge beak, and a concave throat notch — one 9-point polygon (straight edges only, verified non-self-intersecting). It went through several rendered iterations: a full-body silhouette and a circle-plus-beak version both failed to read as "bird" once shrunk to 16px (they degraded to smudges or read as Pac-Man); the profile-head construction with a distinct brow/beak kink is the one that survives 16px. It's reused verbatim across the app icon, mono icon, README logo, spinner, and the `raven` avatar — one shape, one source of truth.
- **Two visual registers.** The flat `currentColor` assets (mono icon, empty states, spinner) spend violet once, as a single accent. The rich brand pair (`icon.svg`, `brand/logo.svg`) works the other way: violet is the ground and the single accent is the **ember-amber eye** — the forge inside the raven. Don't mix the registers within one asset.
- **Self-contained surfaces ignore the theme on purpose.** `brand/logo.svg` and the chronicle parchment (`ForgeChronicle.tsx`) both carry their own palette in every theme, because each is meant to read as an object — a plate on a README, a scroll someone found — rather than a panel of this UI. That is the opposite of the rule above it, and the test for which applies is whether the thing belongs to the app's surface or sits on top of it.
- **The news placeholder echoes the hero backdrop's recipe** (surface gradient + one accent glow + a low-opacity raven mark) so cards sit comfortably against the live scene behind them, but it is built from theme tokens in the DOM — see the table row above for why it stopped being a shipped file.
- **The wordmark's letterforms are constructed, not a real typeface** — a small geometric skeleton-stroke sans (straight segments for R/A/V/E/N/F, true circles/arcs for O/G) built for this lockup only. All strokes use butt caps and miter joins (not round) so every letter carries the same apparent weight — round caps were quietly fattening the diagonal-terminated letters (R/A/V/N) relative to O/G. Letter-gap is intentionally generous (28 units against a 100-unit cap height) for the same reason: those letters overshoot their nominal advance width via cap geometry and looked cramped next to O/G at a tighter gap.
- **The `G` went through three failed constructions** before landing: a ring with a stub spur read as "O with a floating mark"; a ring with a full-width mid-height bar read as lowercase "e"; only opening the ring's aperture asymmetrically in the lower-right (not symmetric about 3 o'clock) and running the spur straight down from the upper terminal _before_ turning inward as a short crossbar reads unambiguously as "G". Arc and spur are one continuous `<path>`, not separate subpaths — with butt caps, two separate paths meeting at a point leave a sliver gap that round caps had been masking. Confirmed legible at 200px, 120px and 60px word width.
- **Every asset here was actually rendered and inspected**, not just checked for valid geometry. This machine has no image rasterizer, but Electron is installed — an offscreen `BrowserWindow` loading an HTML contact sheet, screenshotted over the Chrome DevTools Protocol, gave a real PNG to look at (icons inlined directly as `<svg>`, never `<img src>`, since an `<img>`-referenced `currentColor` SVG doesn't inherit page color and renders black-on-black). The raven mark specifically was iterated through ten-plus rendered candidates at 16/24/32/64/128px before landing on the current shape.

## Deliberately left out / limitations

- **No rasterized outputs** (`.png`, `.ico`, `.icns`) — this machine has no general-purpose rasterizer (no ImageMagick/rsvg/Inkscape/sharp) to batch-export sizes. `icon.svg` is the source of truth; generating platform icon formats from it is a build-time step for whoever wires up `electron-builder`.
- **No favicon/`.ico` multi-resolution bundle** — same reason; `icon-mono.svg` and `icon.svg` are the only shipped forms.
